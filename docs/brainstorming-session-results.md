## 渐进式头脑风暴过程

### Phase 1: 广泛功能探索

#### 核心理念识别
用户提出了明确的愿景：
> "为 SDE 提供最佳博客编辑体验：编辑时 IDE 支持，浏览时静态 IDE 特性"

#### 关键技术特征
- 基于现有代码库生成网站
- 块注释 → Markdown 内容
- 代码 → 可交互代码块
- 静态实现 IDE 特性 (hover, goto definition, folding)
- 不依赖任何框架的纯 HTML 生成

#### 探索方向
1. **编辑体验**: IDE 支持、代码补全、实时预览
2. **网站展示**: 静态 IDE 特性、代码折叠、语法高亮
3. **内容创作**: 代码示例导入、GitHub 集成
4. **用户体验**: 一键复制、在线执行、文档跳转
5. **生态系统**: 社交媒体、技术社区集成

### Phase 2: 核心功能识别

#### 绝对必须的核心功能
1. 解析块注释 → Markdown 转换
2. 代码块的语法高亮 (tree-sitter)
3. LSP 特性集成 (hover, goto definition, folding)
4. JSON 配置文件解析
5. 基本的 HTML 模板生成
6. 简单的文件列表导航

#### 明确延后的功能
- 代码折叠 (非优先级)
- 复杂的导航系统
- 主题系统
- 搜索功能
- 响应式设计优化
- 增量生成

### Phase 3: MVP 聚焦

#### 技术架构决策
- **配置格式**: JSON (.cire.json 文件)
- **项目组织**: 基于目录结构
- **页面结构**: 每个源文件生成一个 HTML 页面
- **样式方案**: 基本 CSS + 充足的 class 名称
- **交互方案**: 最少 JS (hover 功能)
- **语言支持**: MVP 先支持 TypeScript
- **LSP 功能**: hover 文档显示必需

#### MVP 边界定义
**包含功能**:
- 块注释解析 → Markdown 转换
- TypeScript 语法高亮
- Hover 文档显示 (最少 JS)
- Goto definition (页面内/跨页面跳转)
- JSON 配置文件 (.cire.json)
- 基本 CSS 样式 + 充分 class 名称
- 简单文件列表导航
- 命令行错误日志

**明确排除**:
- 代码折叠
- 多语言支持
- 复杂交互功能
- 主题系统

### Phase 4: 实现路径规划

#### 6阶段开发计划

**阶段 1: 基础解析器**
- JSON 配置文件解析 (.cire.json)
- 块注释提取和 Markdown 转换
- 源文件扫描和过滤

**阶段 2: HTML 生成器**
- 基本 HTML 模板系统
- CSS 框架 + 充分的 class 名称
- 每文件一页面的结构生成
- 简单文件列表导航

**阶段 3: Tree-sitter 集成**
- TypeScript 语言支持
- 语法高亮实现
- 代码块结构化

**阶段 4: LSP 集成**
- LSIF/SCIP 索引解析
- Hover 文档提取
- 最小 JS 实现 hover 功能

**阶段 5: Goto Definition**
- 定义位置映射
- 页面内/跨页面链接生成
- 跳转目标标识

**阶段 6: 集成测试**
- 端到端工作流程验证
- 错误处理和日志系统
- 用户文档和使用示例

## 关键技术决策

### 架构原则
- **简单至上**: 纯 HTML + CSS + 最少 JS
- **渐进增强**: 从基础功能开始，逐步添加高级特性
- **技术栈一致**: TypeScript + Tree-sitter + LSIF/SCIP

### 核心工作流程
```
用户编辑代码注释 → 生成 LSIF/SCIP → 运行 Cire 生成器 → 查看静态网站
```

### 数据流设计
```
源代码 → 块注释提取 + 代码解析 → Markdown + 代码块 → HTML 模板 → 静态网站
```

## 创新点与市场定位

### 核心价值主张
- **无缝开发体验**: 在现有开发环境中直接创建技术文档
- **静态 IDE 特性**: 将 IDE 的强大功能带到静态网页中
- **零学习成本**: 基于现有的代码注释和开发习惯

### 技术创新
- **LSP 信息静态化**: 将动态的 LSP 服务转换为静态的网页交互
- **注释驱动内容**: 通过代码注释自动生成结构化文档
- **多语言统一**: 支持多种编程语言的统一文档生成

## 风险评估与缓解策略

### 技术风险
- **LSP 信息复杂性**: 通过 MVP 限制功能范围来缓解
- **浏览器兼容性**: 使用标准 HTML/CSS 确保兼容性
- **性能问题**: 静态生成避免运行时开销

### 产品风险
- **用户接受度**: 通过 MVP 快速验证核心价值
- **功能范围**: 明确 MVP 边界，避免功能蔓延
- **维护成本**: 保持技术栈简单，降低维护复杂度
